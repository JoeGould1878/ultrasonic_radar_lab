2. ALTERNATIVES CONSIDERED (D2)
   Draft, 27 Nov 2026. One block per decision in the decision log
   (docs/PLAN.md). Criteria are the ones the decision was actually judged
   on; nothing here is decided that the log doesn't record. Open decisions
   are listed at the end.

   D-FW  Firmware platform (26 Nov)
     Options:  ESP-IDF v6.1 on the ESP32-S3 / Arduino-ESP32 / Arduino Uno R4.
     Criteria: same toolchain and board as MC2, reproducible builds.
     Chosen:   ESP-IDF v6.1 (pinned; v6.0.2 also installed).
     Evidence: decision log; P0.2 first build (docs/CONTEXT.md, 26 Nov).

   D-ORDER  Build order (26 Nov)
     Options:  SWEEP first, then LOCK and MANUAL / all modes at once.
     Criteria: brief: "keep a working version of the core scanner as you
               experiment".
     Chosen:   SWEEP first; a tagged working version before each extension.
     Evidence: the brief (docs/brief/).

   D-STEP  Sweep step (26 Nov)
     Options:  1 / 2 / 3 / 5 degrees.
     Criteria: SC4 (pass <= 5 s); enough readings on a thin target for
               median-of-3 and edge-midpoint.
     Chosen:   2 degrees: 4.5 s per 150 degree pass at a 60 ms gap, 7 readings
               on a thin target (4 if the useful beam is only 8 degrees).
               1 degree misses SC4 at every gap (9.0 s at 60 ms); 3 degrees
               drops to 2 hits in the 8 degree case, 5 degrees to 1.
     Evidence: docs/evidence/sim/s1_summary.txt (S1). Hardware check: I7.

   D-SCAN  How the servo and the pings are sequenced (26 Nov)
     Options:  stop-and-ping (move, settle, ping) / ping while moving.
     Criteria: pass time (SC4); angle accuracy (SC3, +/-5 degrees).
     Chosen:   stop-and-ping. Pinging while moving saves 0 % at a 40-60 ms
               gap (the move and the 20 ms settle fit inside the gap), and its
               angle error flips sign each pass, so an object jumps 3.2
               degrees between passes (a third of the SC3 band).
     Evidence: docs/evidence/sim/s1_summary.txt. Hardware check: T-MATCH.

   D-ANGLE-TAG  Which angle a reading is tagged with (26 Nov)
     Options:  settled angle at ping time / angle at send time / interpolated.
     Criteria: the reading must be drawn where the sensor was pointing (the
               previous Lab-in-a-Box prototype could be about 2.5 degrees off).
     Chosen:   the settled angle at ping time (follows from D-SCAN).
     Evidence: docs/evidence/sim/s1_summary.txt (assumption A2). Hardware
               check: B1 measures the settle time; T-MATCH.

   D-GAP  Time between pings (26 Nov)
     Options:  30 / 40 / 60 ms.
     Criteria: SC4; no echo from the last ping landing in the next one; the
               sensor must accept the trigger; other teams' sensors.
     Chosen:   60 ms. It already meets SC4 (4.5 s); echoes from up to 10.3 m
               can't land in the next ping (6.9 m at 40 ms, 5.2 m at 30 ms);
               30 ms is shorter than the assumed 38 ms no-echo hold.
               40 ms only if I7, B2 and T-XTALK all justify it.
     Evidence: docs/evidence/sim/s1_summary.txt.

   D-FADE  How long points take to fade (26 Nov)
     Options:  fade over 2 passes / 3 passes.
     Criteria: SC6 (points older than one pass visibly faded) without real
               objects at the arc ends vanishing before they are re-measured.
     Chosen:   3 passes, and expiry after 3 passes. The bounce sweep revisits
               the end bins only every 2 passes, so a 2-pass fade reaches zero
               just as they're refreshed. With 3: 67 % brightness when
               redrawn in the middle, 33 % at the ends.
     Evidence: docs/evidence/sim/s1_summary.txt. Hardware check: O2.

   D-PROTO-NULL  What a no-echo or failed reading sends as its distance (26 Nov)
     Options:  "-" / "0.0" / empty field / -1.
     Criteria: no reader may draw a fake object at 0 cm (honest display).
     Chosen:   "-" for NOECHO and FAIL; OK readings have 1 decimal place.
     Evidence: decision log; the S2 scene logs use it
               (docs/evidence/sim/s2_scenes/).

   D-EDGE  Objects at the arc ends (26 Nov)
     Options:  (a) flag them as low-confidence bearing / (b) overscan about
               8 degrees past each end / (c) narrow SC3 to 30-150 degrees.
     Criteria: SC3 and SC1 unchanged; SC4 (pass time); honest display.
     Chosen:   (a). At 15 and 165 degrees only about 4.5 bins see the object
               and the bearing is pulled about 4.5 degrees inward (worst 5.0).
               (a) costs no sweep time; (b) puts SC4 on the limit (about
               5.0 s); (c) weakens a success criterion.
     Evidence: docs/evidence/sim/s2_summary.txt. Hardware check: T-ANG at
               15 and 165 degrees.

   D-DISPLAY  Where the radar is shown (27 Nov; team agreed)
     Options:  kit screen / PC over USB (Python viewer) / PC over USB (Web
               Serial page in Chrome) / ESP32 web page (PC + phone) / MAX7219.
     Criteria: can it draw positions; works without installing anything;
               effort; reliability in a busy lab; phone access.
     Chosen:   PC view over USB first (tools/radar_view.py), then a web page
               served by the ESP32. The kit screen is probably a character
               LCD that can't show positions, and the PC view doesn't depend
               on the kit. Risk: the lab PC may not run Python and pyserial;
               fallback: the Web Serial page (section 8, R16).
     Evidence: decision log; display spec in docs/PLAN.md.

   D-MODES  Which modes (27 Nov; team agreed)
     Options:  SWEEP plus LOCK and MANUAL / LOCK only / MANUAL only / neither.
     Criteria: the brief's essential scanner first; extensions by value and
               risk (LOCK matches the brief's "rescan a region where an
               object has been detected").
     Chosen:   SWEEP essential; MANUAL then LOCK desirable, in that order.
               MANUAL is simple and reuses the sweep code; LOCK has the most
               to test (SC8).
     Evidence: CONCEIVE section 6; decision log.

8. RISKS AND FAILURE MODES (D8)
   Draft, 27 Nov 2026. Starts from CONCEIVE section 7, plus the electrical
   and display risks. L = likelihood, S = severity, each Low / Med / High:
   our own estimate, to revisit after the tests. "Test" names the test in
   docs/LAB_TESTS.md that checks it.

   Sensing (CONCEIVE section 7)

   R1  Beam smear: a thin object is drawn across several angles
       Cause:      about 15 degree beam (about 26 cm wide at 1 m).
       Effect:     wrong or wide bearing; SC3 missed.
       L / S:      High / Med (S2: a thin tube smears over 7-8 bins).
       Mitigation: edge-midpoint bearing in target_track, bridging one-bin
                   gaps; 2 degree step gives 7 readings to work with (D-STEP).
       Test:       T-ANG.

   R2  Two objects close together merge into one
       Cause:      beam width.
       Effect:     the user sees one object where there are two.
       L / S:      Med / Low (a known limit, shown on purpose at the demo).
       Mitigation: stated as a limit (CONCEIVE section 7); S2 predicts merging
                   below about 17-18 degrees.
       Test:       T-TWO.

   R3  Angled flat surface gives no echo (specular reflection)
       Cause:      sound bounces away from a smooth surface at an angle.
       Effect:     a wall or box is invisible: "no echo" taken as "clear".
       L / S:      High / High (the most misleading failure).
       Mitigation: the display never says "clear"; NOECHO is drawn as its own
                   mark (faint dash at max range, display spec); S2 predicts
                   no echo beyond about 40 degrees tilt at 50 cm, 35 at 100 cm.
       Test:       T-MAT (tilted T2).

   R4  Soft materials absorb the sound
       Cause:      cloth, foam, clothing.
       Effect:     object missed, as R3.
       L / S:      Med / High.
       Mitigation: as R3; recorded as a limit.
       Test:       T-MAT (T4).

   R5  Small target smaller than the datasheet assumes
       Cause:      the datasheet's 3 mm accuracy assumes a flat, smooth target
                   of at least 0.5 m^2; our SC1 target is a 5 cm tube.
       Effect:     weaker echo, dropouts, worse accuracy than the datasheet.
       L / S:      Med / Med.
       Mitigation: SC1 judged on our own measurements, not the datasheet.
       Test:       T-DIST (T1 part), T-MAT.

   R6  Objects at the arc ends get a biased bearing
       Cause:      only half the smear is seen at 15 and 165 degrees.
       Effect:     bearing pulled about 4.5 degrees inward (worst 5.0, S2).
       L / S:      High (whenever something is at the end) / Low.
       Mitigation: D-EDGE: edge flag, bearing shown as low confidence.
       Test:       T-ANG at 15 and 165 degrees.

   R7  Moving objects are in the wrong place; SWEEP can't follow a walker
       Cause:      a point is revisited only every 1-2 passes (4.5-9 s).
       Effect:     old position shown as current.
       L / S:      High / Med.
       Mitigation: fading by passes (D-FADE); LOCK revisits a narrow sector
                   much more often.
       Test:       T-MOVE, T-LOCK.

   R8  Old point shown as current; readings stop without anyone noticing
       Cause:      fading too slow, or the data stream stops (cable, crash).
       Effect:     user trusts an out-of-date picture.
       L / S:      Med / High.
       Mitigation: fading (D-FADE); global STALE banner after 1.5 s with no
                   reading (APP_STALE_MS), also when the port or socket drops.
       Test:       T-STALE.

   R9  Wrong angle because the servo has not settled
       Cause:      pinging before the servo stops (the Lab-in-a-Box bug).
       Effect:     object drawn where it is not; jumps between passes.
       L / S:      Med / Med.
       Mitigation: stop-and-ping with a settle time (D-SCAN, D-ANGLE-TAG);
                   B1 measures the real settle time.
       Test:       T-MATCH, T-ANG.

   R10 Cross-talk from other teams' sensors, or a late echo
       Cause:      every HC-SR04 uses 40 kHz; a far echo arriving after the
                   next ping.
       Effect:     phantom objects.
       L / S:      Med (a busy lab) / Med.
       Mitigation: 60 ms ping gap (D-GAP); echoes beyond the timeout ignored.
       Test:       T-XTALK.

   R11 Speed of sound changes with temperature
       Cause:      about 0.17 % per degree C.
       Effect:     distances shift slightly (about 0.5 cm at 150 cm for 2 C).
       L / S:      Low / Low.
       Mitigation: record the room temperature with T-DIST.
       Test:       T-DIST (note only).

   Electrical

   R12 Servo current through the board's 5 V / USB causes a brown-out
       Cause:      the SG90 draws a current spike when it starts and when it
                   stalls; it is fed from the board's 5 V pin, which comes
                   from the PC's USB port (500 mA for USB 2.0). Exact figures
                   come from the SG90 datasheet in D4.
       Effect:     ESP32 resets mid-sweep, or the sensor reads wrongly.
       L / S:      Med / High.
       Mitigation: 470-1000 uF bulk capacitor at the servo (value from D4);
                   servo moves first at start-up (main.c order); servo
                   released when paused; separate supply if B1 shows resets.
       Test:       B1 (watch for resets), T-POWER (current per mode).

   R13 5 V ECHO on a GPIO (only if the kit sensor is the 5 V HC-SR04)
       Cause:      the 5 V HC-SR04's ECHO output is 5 V; ESP32-S3 pins are
                   3.3 V.
       Effect:     damaged GPIO or chip.
       L / S:      High without the divider / High.
       Mitigation: 1 k / 2 k divider to 3.3 V; no divider if the kit has the
                   3.3 V HC-SR04P (B4 decides).
       Test:       B2 (measure ECHO at the GPIO, <= 3.3 V).

   R14 ECHO on a pin that may not be 3.3 V (was GPIO47)
       Cause:      on the ESP32-S3, GPIO47 and GPIO48 are in the flash/PSRAM
                   supply domain (VDD_SPI), which is 1.8 V on modules with
                   1.8 V memory (from memory of the ESP32-S3 datasheet; not
                   re-checked).
       Effect:     a 3.3 V ECHO into a 1.8 V pin could damage it, or the
                   level is read wrongly.
       L / S:      Low-Med (depends on the module) / High.
       Mitigation: done on paper, 27 Nov (Joe): ECHO moved to GPIO 9, a plain
                   3.3 V pin, not a strapping pin, freed when the screen pins
                   were removed (APP_PIN_US_ECHO, PROPOSED). The risk is now
                   only that D6 changes the pin back without this check.
       Test:       D6 pin check (no LAB_TESTS test); B2 measures ECHO at the
                   GPIO.

   R15 Flexing sensor wires break
       Cause:      the sensor rides on the servo, so its 4 wires bend on
                   every sweep.
       Effect:     intermittent FAIL readings or a dead sensor.
       L / S:      Med (over a long demo) / Med.
       Mitigation: service loop, strain relief, connector (D5); FAIL shown,
                   not hidden.
       Test:       T-FAULT (unplug), I11 (T-DIST re-run after the mount).

   Display and use

   R16 The lab PC can't run Python (no pyserial, no install rights)
       Cause:      locked-down lab PCs.
       Effect:     no core display at the demo.
       L / S:      Med (unknown) / High.
       Mitigation: check in session 2 (PLAN Open questions); fallback: a Web
                   Serial page in Chrome, nothing to install; or our own
                   laptop.
       Test:       none in LAB_TESTS; a session 2 check.

   R17 Sensor fails or is unplugged; reading shown as 0 cm
       Cause:      loose wire, dead sensor.
       Effect:     fake object at 0 cm.
       L / S:      Med / High.
       Mitigation: FAIL status, "-" not 0 (D-PROTO-NULL); FAIL drawn as a
                   cross; FAULT banner.
       Test:       T-FAULT, B2.

   R18 Over-trust of a radar-style display
       Cause:      it looks authoritative.
       Effect:     users trust missed or old data.
       L / S:      Med / High.
       Mitigation: the display spec: statuses by shape, fading, STALE banner,
                   never "clear" (CONCEIVE sections 7 and 9).
       Test:       O2 (outsider can tell which points are old).

   R19 Animals hear 40 kHz
       Cause:      40 kHz is within the hearing of cats and some dogs.
       Effect:     distress to pets nearby.
       L / S:      Low (in a lab) / Low.
       Mitigation: don't leave it running near pets (CONCEIVE section 9).
       Test:       none (operating rule).
