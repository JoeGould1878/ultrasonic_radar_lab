    Why: a resweep starting at a sector end goes to the far arc end first (turnaround leg), then one
    full pass: 5-7.5 s with the beam away. At 5 cm/s (5.5 deg/s) the target moves 25-40 deg, more than
    the 15 deg gate -> on_pass gate fail. If it is kept, the sector is re-entered at the bearing the
    resweep measured when it crossed the target (already the rule), but the servo first walks back
    from the arc end (up to ~3 s), so on its 1st sector pass the target has left the sector ->
    on_ping misses. Both losses are the resweep's duration, not the sector following.
3b  One fix (EXPERIMENT, not the default): defer a due resweep while the measured angular speed
    (last 3 sector pass ends) is > 3 deg/s. Re-entering at the crossing bearing was not
    tried: lock_loop already does that (go_sector uses the resweep's cluster).
    Result: no better. In the back-and-forth movement the speed only drops at a turnaround, so
    the deferred resweep fires there and the target then moves away at full speed during it.
    Defer helps only a target that really stops (a still target still gets every resweep, see below).
